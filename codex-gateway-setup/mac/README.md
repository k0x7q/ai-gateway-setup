# macOS Codex 网关配置

## 使用

1. 推荐使用[项目首页](<../../README.md>)中的在线启动命令。离线运行时，保持启动文件和“辅助文件”文件夹在一起，通过终端传入网关地址再运行[启动文件](<双击此文件配置 Codex.command>)：

   ```bash
   AI_GATEWAY_URL='https://gateway.example.com' /bin/bash './双击此文件配置 Codex.command'
   ```

   示例地址需替换为实际 HTTPS 网关域名或 IPv4 地址，可带端口及末尾 `/`，不要添加 `/v1` 或其他路径。未提供地址时停止。实际地址只保留在内部命令中，不提交到公开仓库。
2. 没有可复用密钥时，弹窗输入网关密钥，输入为明文。有可复用密钥时，先选择“使用现有密钥”或“输入新密钥”；确认窗口不显示旧密钥。
3. 保存及验证自动进行，成功后自动请求打开 Codex 并结束，没有成功确认弹窗。配置过程中不要提前关闭启动窗口。
4. 如果 Codex 正在运行，保存工作并退出后点击“重试”；如果未检测到应用，安装后重新检测或选择继续配置。本工具不安装或强制关闭应用。
5. 失败时显示错误编号、阶段、原因、可确定时的行号和配置状态，支持“复制诊断信息”。网络验证失败时配置已经保存，且本次不会自动打开应用；修复后可重新运行。诊断不附带密钥或配置正文。

macOS 可能要求确认打开下载的脚本，或要求允许终端使用“系统事件”查看运行中的应用。请自行检查文件和权限后决定是否允许；本工具不会修改系统安全设置。若操作被系统阻止，请勿通过关闭安全功能来强行运行。

## 配置与安全

- 使用当前用户的 `~/.codex/config.toml`；若设置了 `CODEX_HOME`，必须指向已存在的目录（建议使用绝对路径），否则停止。配置目录必须由当前用户拥有，不能是符号链接、不能允许群组或其他用户写入，且不能有 ACL；不满足时停止。已有文件的原内容备份在同一目录，文件名以 `config.toml.backup-` 开头；新配置和备份创建时清除继承 ACL 并检查权限为仅当前用户读写（0600）。备份也可能包含密钥，请妥善保管，按需自行删除。替换文件会改变原配置的 inode、权限和 ACL；备份保留内容但不保留原权限或 ACL。
- 输入框为明文输入；密钥也以明文保存在 Codex 配置和旧配置备份中。请确保配置目录没有会授予其他用户访问权限的特殊 ACL，也不要把配置或备份分享出去。
- 保留已有顶层 `model`；缺失时设置 `gpt-6.1-sol`。仅当原 `custom` 的 HTTPS 地址为指定主机及 `/` 或 `/v1`（允许末尾斜杠），且原密钥非空时，才允许弹窗确认复用旧密钥；否则提示输入新密钥。
- 为防止破坏配置，内置编辑器只接受严格的 TOML 子集。多行字符串、点分赋值键、行内表、数组表、多行数组、日期时间、重复定义及其他不能确认安全的语法会被拒绝；原配置不会被编辑。普通带引号的表名（包括项目路径和插件名）受支持。需要更复杂配置时请先自行备份，并由熟悉 TOML 的人员处理。
- 配置文件是符号链接时拒绝修改。已有配置写入前会检查文件是否发生变化并以临时文件替换，但无法杜绝检查与替换之间的极短竞态；请确保没有其他程序同时修改配置。系统突然断电时也不能保证目录项持久性。
- 只通过已知 `com.openai.codex` bundle ID 与 `ChatGPT`/`Codex` 可执行文件名发现应用；这是身份匹配，不是签名真实性验证。应用也可能因未索引或其他名称而未被发现。
- 需要 macOS 自带的 `/usr/bin/ruby`、`osascript`、`curl` 等系统工具；若系统 Ruby 不可用则停止，不安装开发者工具或其他依赖。验证时不会跟随重定向；非可打印 ASCII 密钥可安全存入 TOML，但网络验证会显示明确的密钥格式错误。

## 开发者测试

在本目录执行 `/usr/bin/ruby 辅助文件/test_setup.rb`。测试使用辅助文件目录下的临时目录，不读写真实 Codex 配置，也不启动 GUI、发送网络请求或打开应用。实机 GUI 授权、手动下载和实际网关连通性需另行人工验证。
