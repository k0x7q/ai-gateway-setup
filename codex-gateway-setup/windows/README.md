# Windows：Codex 网关设置

推荐使用[项目首页](<../../README.md>)中的在线启动命令。使用 Windows 10/11 自带的 Windows PowerShell 5.1 和 WinForms，不安装 PowerShell 7、Python 或其他软件。启动器只为本次 PowerShell 进程使用 ExecutionPolicy Bypass，不更改系统策略。

离线运行时，保持启动文件和“辅助文件”文件夹在一起，在 PowerShell 中传入地址并运行[启动文件](<双击此文件配置 Codex.cmd>)：

```powershell
$env:AI_GATEWAY_URL = 'https://gateway.example.com'
& './双击此文件配置 Codex.cmd'
```

示例地址需替换为实际 HTTPS 网关域名或 IPv4 地址，可带端口及末尾 `/`，不要添加 `/v1` 或其他路径。未提供地址时停止。实际地址只保留在内部命令中，不提交到公开仓库。

## 操作流程

- 没有欢迎或验证等待确认弹窗。未检测到 Codex 时，只提供“重新检测”“继续配置”“取消”；继续后可完成配置，但需自行打开应用。
- 检测到 Codex 正在运行时，提醒保存工作并自行关闭，可重试或取消；不强制结束进程。检测仅覆盖常见安装位置、开始菜单以及名为 Codex 的进程，不能保证识别所有安装方式或后台进程。
- 没有可复用密钥时，弹窗明文输入，提示仅为“请输入网关密钥”。检测到可复用密钥时，也会弹窗确认，提供“使用现有密钥”“输入新密钥”“取消”；不显示旧密钥。只有同一准确网关地址下的非空原密钥可供复用。输入取消或空白时结束，不保存。
- 保存后显示简短、无确认的验证进度。验证成功且检测到可启动的应用时，自动请求启动 Codex，然后结束，不弹成功确认。如启动失败、应用未检测到或验证期间自行启动了 Codex，会给出诊断并明确配置已保存；不会强制杀进程或启动重复实例。

## 失败诊断

失败窗口提供“复制诊断信息”和“关闭”，包含稳定编号、失败阶段、具体安全原因、异常类型与 HResult、配置状态。编号 W001–W008 分别对应路径、读取、解析、生成、保存、验证、启动、初始化/设置，W009 为应用检测/运行检查，W010 为密钥选择/输入；HTTP 验证失败带 `W006-HTTP-状态码`，传输异常带 `W006-NET`。剪贴板不可用时可在诊断文本框中自行选中复制。

解析错误尽可能提供 TOML 行号，不显示该行文本。固定的解析/安全检查异常给出具体原因；文件、权限和原生 Windows 异常以异常类型、HResult 或数字系统错误及其系统说明定位。其他异常显示脱敏后的具体 Exception.Message，过滤当前密钥原文及转义变体、认证信息和疑似配置格式内容，并保留类型与 HResult。诊断不输出密钥、认证标头、配置内容、响应正文、ErrorRecord、行文本或调用栈。

状态明确区分：未进入保存时内容与权限未由本工具修改；保存过程中失败时可能已有权限变动、临时文件或备份；原子替换/移动发生异常时结果未确认，不能断言原配置没改；内容写入后若最终 ACL 或后续验证/启动失败，仍标记“已保存”。不要直接删除或清空原配置。

## 配置与安全边界

配置写入当前用户的 `CODEX_HOME\config.toml`（环境变量是受支持的本地绝对目录路径时），否则写入 `%USERPROFILE%\.codex\config.toml`。无效 `CODEX_HOME` 会停止，不会悄悄换路径。不支持 UNC、映射网络盘，或配置文件、目录及任何已有上级目录的链接/重解析点。读取和写入前检查目录链，但不能防止其他进程在检查后立即替换目录；请避免同时修改目录、配置或权限。

原有模型保留，无模型时使用 `gpt-6.1-sol`。密钥以明文保存在配置及可能的备份中。配置和新备份尝试限制为当前用户可访问，但管理员访问、Windows 文件系统权限、ACL 继承及其他本机软件仍影响实际保密性。历史备份不清除，需自行安全管理。

保存仍使用同目录私有临时文件、随机名称原内容备份与原子替换；备份不保留原 ACL 等元数据。替换前会收紧并验证原文件 ACL，即使后续保存失败，ACL 也可能已经改变。读取后发现配置内容变化时停止覆盖；这不是跨进程事务锁，不能消除检查后的竞态。本次仅增加保存状态记录，不扩展解析或保存支持范围。

仅支持保守 TOML 子集：普通键、单行字符串、布尔值、简单数值、单行字符串数组（含空数组）以及可含引号路径分量的普通表。其他数组、内联表、多行字符串、点分赋值键、数组表、重复键/表、键与表冲突会拒绝，不尝试重写不认识的内容。

验证请求固定 `/v1/models`，不跟随重定向，15 秒超时。2xx 只代表该请求成功，不保证后续全部功能。401、403、404、429、重定向及服务端错误分别报告状态码；超时、连接、DNS、代理 DNS、TLS 信任/安全通道等异常分别报告，验证失败不等于配置未保存。请求可能经过系统代理，密钥只通过 HTTPS 请求认证标头发送给固定网关，不加入网址或启动参数。

## 开发者自测

[SelfTest.ps1](<辅助文件/SelfTest.ps1>) 使用合成密钥和脚本目录下新建的 `test-output-*` 子目录，不读取真实 Codex 配置、不发送网络请求、不打开 GUI。运行命令：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\辅助文件\SelfTest.ps1
```

覆盖 PowerShell AST 语法检查、UTF-8 BOM、密钥弹窗选择流程（模拟）、诊断脱敏与行号、HTTP/传输分类、保存状态矩阵、早期保存失败注入、保守解析、密钥转义、原密钥网关匹配、配置 BOM、备份、并发变化与真实成功保存状态。若环境允许创建目录联接，还会测试配置目录和上级目录的联接拒绝，否则明确输出跳过。输出目录、模拟备份和测试联接留待开发者自行清理。

保存后 ACL 失败及原子操作结果不确定由合成状态矩阵覆盖，不声称已注入所有真实 Windows 文件系统故障。GUI/剪贴板、真实应用检测与启动、真实 HTTP/TLS 和完整 ACL 场景仍需 Windows 实机验证。当前修改环境没有 `pwsh` 或 Windows PowerShell，因此只做静态检查，未实跑自测，也未安装任何运行时。
